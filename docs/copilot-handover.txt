Arena Control System - Project Context
Overview

This project is an arena control system for a combat robotics / BattleBot style arena.

The system consists of:

Front End
Static HTML pages hosted on IIS
Authentication via PIN login
Role-based access control using sessionStorage token

Node.js Express API (server.js)

Crane Commands
Home

Endpoint:

POST /api/crane/home


Executes:

G28


A special version of the route exists because Moonraker occasionally returns odd responses after homing.

Route is tolerant and treats most responses as success.

Move

Endpoint:

POST /api/crane/move


Body:

{
  "command":"X10"
}

X10
X-10

X-100

Y10
Y-10

Y-100

Z10
Z-10

(or equivalent)

Fire

Endpoint:

POST /api/crane/fire


Current behaviour:

G90
G1 Z17 F3000
M106 S255


Purpose:

Move crane Z to 17
Turn solenoid ON
Release

Endpoint:

POST /api/crane/release


Current behaviour:

M106 S0
G90
G1 Z250 F6000


Purpose:

Turn solenoid OFF
Raise crane to Z250

No homing occurs.

Klipper Configuration Notes

Current Z configuration:

[stepper_z]
step_pin: PB5
dir_pin: !PB6
enable_pin: !PC3
microsteps: 16
rotation_distance: 8
endstop_pin: ^PA7
position_endstop: 363
position_max: 363
position_min: -10


Do NOT modify:

rotation_distance


to increase speed.

Speed should instead be controlled through:

max_z_velocity
max_z_accel


and G-code feedrates.

Stepper Holding

Problem:

Klipper forgets position when motors disable.

Recommended solution:

[idle_timeout]
timeout: 86400


Optional:

hold_current


if using TMC drivers.

Avoid:

M84


which disables motors.

Current Known Issues
1

Moonraker sometimes returns unusual responses after:

G28


Result:

Frontend may show:

500 Could not home crane


even though homing actually worked.

Use the tolerant home route.

2

Windows Server 2012 may shut down automatically if activation/evaluation period has expired.

Check:

slmgr /dli


and restore proper activation.
